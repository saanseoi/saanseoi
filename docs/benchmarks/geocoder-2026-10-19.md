# Geocoder evaluation and basemap coverage

The fixed sample contains 25 Google Maps florist listings across ten Hong Kong areas,
with one reverse pin, one complete listed address and one manually simplified address
per listing. Google is a reference, not surveyed ground truth. Floor/shop detail is
outside the building/street comparison. The sample is small and purposive.

## Scope and reproducibility

The reference fixture is copied unchanged from Hype to
[`scripts/geocoding/fixtures/florists-2026-10-18.json`](../../scripts/geocoding/fixtures/florists-2026-10-18.json).
Hype's unchanged benchmark runner supplies all 75 queries, `profile=map`, `limit=5` and
`maxDistance=1000`. Distances use included address geometry, not an input pin.

The local serving release is `data-hk-addresses-2026-09-23.0`. The handover used
`data-hk-addresses-2026-09-22.0`; this is therefore not a controlled same-release
before/after comparison. An explicit 22 September historical query timed out after 45
seconds. The shared development API also stalled on subsequent current queries. An
isolated local Worker on port 8794 uses a consistent copy of META and the current
Address serving tables, indexes and publication receipts. This separates matching
verification from the shared server's availability. Production credentials, CORS and
production readiness are not established by this run.

Run from Hype:

```fish
bun test scripts/geocoding/benchmark.test.ts
bun scripts/geocoding/benchmark.ts --base http://localhost:8794 --continue-service-errors --output /tmp/florists-results.json
```

## Fixed-sample results

All 75 final requests returned HTTP 200 on the first attempt. Results and manual
judgements are retained in the [responses](geocoder-2026-10-19.responses.json) and
[review](geocoder-2026-10-19.review.json) artefacts.

| Query                   | Candidates | Strict top-1 agreement | Strict top-5 agreement | Ambiguous | Median time |
| ----------------------- | ---------: | ---------------------: | ---------------------: | --------: | ----------: |
| Reverse pin             |      25/25 |            16/25 (64%) |            21/25 (84%) |     17/25 |      489 ms |
| Complete listed address |      24/25 |            22/25 (88%) |            22/25 (88%) |     14/25 |       76 ms |
| Simplified address      |      24/25 |            19/25 (76%) |            21/25 (84%) |     14/25 |       70 ms |

Under the requested numeric-stem policy, ignoring suffix distinctions, top-1/top-5
agreement is 17/25 and 23/25 reverse, 24/25 and 24/25 complete, and 21/25 and 23/25
simplified. This additional view must not be read as verification that `139` is `139A`,
or `164A` is `164`. Strict scores preserve the original rubric's suffix distinctions.

Distance is separate from identity: top results were within 100 metres for 25 reverse,
23 complete and 21 simplified queries. The first reverse result can be two metres away
and still disagree with the reference. Bare Gold Coast and Novo Land queries also
illustrate why street-number agreement and point distance answer different questions.

The longest complete/simplified requests were 11,358/10,808 ms, both unmatched Tai Wai
Market fallback scans. The longest reverse request was 1,413 ms. These are local
measurements with copied serving tables, not production latency promises or a controlled
speed comparison against the handover's shared-server measurements.

The handover recorded 0/25 complete-address candidates, 15/25 simplified top-1 agreement
and 16/25 reverse top-1 agreement. The new run establishes useful forward behaviour and
explicit reverse uncertainty, but release and server differences prevent attributing all
changes to code. Reverse rank accuracy is not claimed to improve.

## Matching contract

Parsed numbers use the published numeric-stem index. Street tokens, number intervals,
range parity and named buildings determine ranking. Floor/unit labels are excluded; road
abbreviations, directions, punctuation and Chinese phase numerals are normalised. The
model-limited numeric-stem policy ignores letter suffixes. This allows `139A` to
retrieve `139` and `164` to retrieve `164A`, but cannot verify suffix-specific identity.
Strict reference agreement below keeps those two cases distinct from successful stem
retrieval. Locality prefixes such as On Ning Road versus Yuen Long On Ning Road are
weaker interpretations, not asserted publisher aliases.

Unparsed strings first try named/formatted components, then a normalised scan if needed.
This fallback is deliberately slower. Tai Wai Market remains unmatched; matching only
the Tai Wai estate/locality does not establish a market identity. Bare addresses at One
IFC, Lee Tung Avenue, Novo Land and Gold Coast retain multiple facilities. Building
qualifiers improve selection without inferring the user's intended facility.

Reverse ranking uses address-point distance. Results explicitly identify this evidence,
return candidate coordinates and flag ambiguity when the second distance is within 15
metres of the first. This threshold is a selection heuristic, not measured pin accuracy.
It does not establish footprint containment or prove uniqueness outside the threshold.
The distance prefilter handles longitude as well as latitude, including the antimeridian
and poles.

## Basemap and address coverage

The audit reads the exact retained OSM extract for basemap `hk/2026-10-01`, SHA-256
`470c2396f11f2e4d689260ddc5583dea215133773097b93f2f508a10d7fbdd63`, matching the
published release statistics. It uses source polygons rather than clipped/simplified
vector tiles. Source ways and relations can overlap; these are not deduplicated counts
of physical buildings. The address side uses the current publication receipts recorded
in the [coverage artefact](geocoder-2026-10-19.coverage.json).

| Measurement                                  |           Count |
| -------------------------------------------- | --------------: |
| Valid OSM building polygons                  |         119,229 |
| Polygons with a name                         |          35,311 |
| Polygons with street and house-number tags   |          25,510 |
| Current address points with coordinates      |         182,756 |
| Address points inside at least one footprint | 113,281 (62.0%) |
| Sample pins inside at least one footprint    |     21/25 (84%) |

Coverage is not identity agreement. Notable containment evidence:

| Reference            | Footprint evidence                                                 | Implication                                        |
| -------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| One IFC              | One International Finance Centre, with one canonical address point | Useful building evidence                           |
| Lee Tung Avenue      | Footprint contains the Lee Tung Avenue address point               | Useful building evidence                           |
| 10–16 Kin Tak Street | Kin Tak House footprint and its address point                      | Promising correction to proximity ranking          |
| 75 Yeung Uk Road     | Footprint tagged 71–73; contains the 71 address point              | Containment conflicts with the reference           |
| Kings Wing Plaza 1   | Pin outside all audited building footprints                        | Footprints cannot resolve this pin                 |
| Fu Tung Market       | Fu Tung Plaza footprint and plaza address point                    | Footprint alone cannot identify the market         |
| 13 Swatow Street     | Yee Kan Court / 12 Swatow Street                                   | Pin or source geometry needs review                |
| 4 Tsing Yuen Street  | Footprint contains 1 Wai Yan Street                                | Alternate frontage or pin discrepancy needs review |

Basemap-only geocoding would lose canonical address coverage and often lack an address
label. Combining datasets is promising, but neither point containment nor nearest
centroid alone is a safe building-to-address identity rule. Entrances were not
systematically inventoried in this audit.

## Proposed additional processing

Prepare a release-pinned spatial evidence index alongside the canonical address
publication. Retain OSM object identity, source digest, unsimplified polygons, bounding
boxes, address-point links, named/numbered frontage agreement and conflicting links. Use
an R-tree or existing spatial-cell infrastructure to narrow nearby points and footprints
before precise distance/containment calculations. Avoid reading PMTiles and
reconstructing clipped polygons on each request.

Separate link quality from query-pin evidence. A footprint whose name and numbered
frontage agree with one canonical building is stronger than containment alone. Preserve
multiple addresses for corner buildings, multiple facilities within complexes and
independent overlapping footprints. Include relevant entrances in a subsequent source
extract and verify their building/frontage associations. Do not move canonical points or
merge address identities merely to improve this benchmark.

A future selection policy should expose footprint, entrance and point evidence with
conflicts and alternative candidates. Validate its improvement on this fixed sample and
a separate broader sample before enabling automatic footprint promotion. The four
conflicting cases above are required negative tests, not exceptions to hide.

The read-only audit is [`coverage.py`](../../scripts/geocoding/coverage.py). It requires
`osmium` and Python Shapely 2:

```fish
osmium tags-filter .local/tiles/sources/refresh-hk-2026-10-01.osm.pbf w/building r/building -o /tmp/geocoder-buildings.osm.pbf
osmium export /tmp/geocoder-buildings.osm.pbf --add-unique-id=type_id -f geojsonseq -o /tmp/geocoder-buildings.geojsonseq
python scripts/geocoding/coverage.py --address-db /path/to/DB_CURRENT.sqlite --footprints /tmp/geocoder-buildings.geojsonseq --fixture scripts/geocoding/fixtures/florists-2026-10-18.json --output /tmp/geocoder-coverage.json
```
